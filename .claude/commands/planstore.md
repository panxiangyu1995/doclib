会话规划与收尾纪律（planstore），分四段执行：

【规划落盘】将想达到什么目的和效果、问题点、研究结果、代码实际情况，设计的方案、有无备选方案、具体的实施清单还有验收标准等内容保存成文档进 .plan 目录下今日日期的文件夹内（文件名用规划主题 slug，kebab-case）。

【反遗漏自检】规划文档落盘前逐项核对以下信息是否已写入，遗漏则补记：
1. 用户中途的纠正与拍板理由（保留原话要点，不做丢失语义的转述）
2. 被否方案及否决理由（每个备选为什么不行）
3. 失败尝试与踩坑（95-lessons 的上游素材，即使最终绕过也要记；入馆去向经 progress.md 条目末「教训:」处置位登记——check「教训账缺口」执法）
4. 验收口径的变更过程（中途改了什么标准、为什么改）
5. 跨会话前情（本会话依赖哪些更早会话的结论，给出文件指针）

【踩坑一行制（实时，β）】开发中每踩一个坑（报错/返工/预期失手/重踩旧坑），**当下**就在当前 .plan 规划文档「失败尝试与踩坑」节追加一行（日期 + 现象一句话）——只记一行，不等收尾、不打断主流程；lessons 四段蒸馏留给收尾。防会话中断永久丢失上游素材（check 执法不了「何时记」，收尾核对兜底）。

【会话收尾五动作】开发完成或会话结束前依次执行：
1. 踩坑回填与教训入档核对：逐条对照本会话 .plan 文档「失败尝试与踩坑」节 vs progress.md 教训处置位——每个坑必须已回填第九节（上游素材）、已蒸馏进 95-lessons（四段+来源: 行）或在处置位声明去向；蒸馏时把「来源:」行写真实路径（check「教训来源缺失」执法：epoch 后条目必带来源行且路径存在）
2. 刷新记忆快照：更新 `.doclib/guide-memory.md`（`work-as-of` 落今日；协作者画像有新观察时更新 `user-as-of` 与对应条目，每条附真实路径指针）→ `doclib sync` 注入（status「记忆」行滞后 ⚠ 即提示刷新）。
3. 提醒用户在会话内执行工具原生导出（OpenCode 输入 /export 后在编辑器另存；Claude Code 与 Codex 输入 /export <文件> 直写），落位 doclib/98-sessions/，文件名 <slug>-<yyyymmdd>-<NN>.md（slug 与本会话的 .plan 文档一致，同 plan 多会话递增 NN），并在导出件补 frontmatter 五要素（type: transcript、tool、session-id、date、plan-slug）。
4. 在对应 .plan 文档头部「会话导出登记」段登记导出文件名（双向关联）。
5. 导出前自查对话中是否出现敏感信息（密钥/token/凭据），有则提醒用户，并在 .plan 文档的导出登记处注明警示。
