# doclib-audit · 图书馆质量审计

## 使命

回答"图书馆够不够好"：类别无静默缺漏、粒度恰当、内容可信、经得起陌生 agent 提问。

## 何时使用

- `doclib verify` 覆盖度报告之后（verify 管"有没有"，audit 管"好不好"）
- 定期体检（里程碑/版本发布前）
- 图书馆结构演进（基线/册制/索引规范变更）后

## 工作流

1. **类别完备性**：对照 12 卷基线 + 增补清单逐卷判定——已覆盖 / 缺失 / 不适用（显式声明+理由）。**禁止静默省略**；缺失卷产出建卷建议
2. **覆盖粒度判断**：抽读 covers——目录级 covers 是否该细化？登记簿条目五要素（标识/实体级 covers/契约细节/状态机/时间线）是否俱全？缺口列补账清单
3. **终极抽查**（陌生 agent 视角自问，答不上的即图书馆缺陷）：
   - 五问：部署方式？核心数据流？任一功能边界行为？错误处理策略？配置项全集？
   - 实体查询：任一 API 请求/响应结构？某图标用在哪些页面？某次重大更新为何而改？
4. **文档质量抽查**：示例代码片段与真实 API 签名比对（片段可选 covers 锚定）；截图/图表时效性；近似重复文档检测（多胞胎改一漏三）
5. **可读性抽查（文体学语义档——PRD §7.6 v0.32）**：机器门禁（verify/check 管"结构在不在"）之外，随机抽 narrative 叙述文档按**教科书三问**逐篇裁决——①为什么讲清了吗（动机/设计决策可考）？②新手能顺着读吗（导读→三段递进成立，无需跳读源码）？③agent 能直达吗（导读可作摘要、交叉引用可导航）？另查：粒度合理性（一篇书一个主题——过薄卡片化/过厚难导航均登记）；注记污染人工复核（机器已拦实验编号/答卷日期，语义级残留如"待精读/暂记"口语一并清）——不合规项列入审计报告"表述"类
6. **旗标对账候选裁决**：verify 旗标面的双向 Δ 候选逐项裁决——源有馆无=补登记或标注非实体；馆有源无=虚构/过时/被否（登记状态机）或**外部工具旗标引用**（deploy/integration 语境的 git/npm 等属合法引用，裁决留痕）；规范文档中的示例 token 一律抽象措辞（防自指误报，同 POLLUTION_PATTERN 纪律）
7. **孤儿误报排查**：`doclib check` 报出的孤儿先判是否误报——agent 工具目录（含尚未内置闭集的新工具）、第三方/vendor、测试夹具、嵌套引导文件。误报=缺陷（剔除列滞后于生态），登记为「剔除列提案」：能用 `doclib ack --dir <前缀> --note "<理由>"` 零代码豁免的立即豁免；确需扩内置闭集的记为基线演进提案（ADR + PRD 授权）
8. **产出审计报告**：按卷列出 缺陷（内容/结构/表述/验收四分类，同 F14 缺陷分类学）+ 修复优先级；结构缺陷单独标注（触发基线/PRD 演进）
9. **收尾**：修复项转 doclib-dev 循环；`doclib check` 确认无新增违规

## 纪律

- 抽查按"先馆后码"执行：先凭馆作答，再读码验证——答错的不是 agent 是图书馆
- 四分类处置：内容→补账；结构→基线演进提案；表述→skill/模板改进；验收→30-features 模板修正
