# doclib-build · 项目蒸馏为文档图书馆

## 使命

把一个真实项目蒸馏成一座纯 Markdown 的文档图书馆，使其成为"足够完整的规格书 + 架构蓝图 + 实施指南"。验收标准只有一条：**陌生的 agent 只读图书馆、不看源码，能在别处从零开发出功能 ≥90% 复原的项目。**

## 何时使用

- 项目里已运行 `doclib init`，且 `doclib plan` 生成了 BUILD 任务书（位于 `.doclib/tasks/`）
- 已有图书馆残缺/严重过时，需要系统性重建

## 工作流

1. **读任务书**：打开 `.doclib/tasks/` 下最新 BUILD 任务书，其中含 CLI 采集的项目清单（语言/框架/规模/入口/顶层结构）
2. **三遍扫描源项目**（这是唯一需要通读源码的阶段，之后一切以文档为准）：
   - 第一遍·骨架：清单文件、入口、路由/页面/命令清单、目录职责、依赖图
   - 第二遍·数据：数据模型/Schema/存储格式/接口契约/配置项全集
   - 第三遍·行为：逐功能梳理触发方式、正常路径、边界、错误、并发/幂等/性能约束
   - **图谱加速（可选）**：项目已建知识图谱（.codegraph/ 存在）时，`doclib graph draft` 产出 .doclib/drafts/ 四册候选（routes/modules/dependencies/unused），第一遍·骨架以此枚举兜底，`doclib graph explore <query>` 替代 grep 循环——**图输出只是候选，禁止直接入馆**：routes/modules/dependencies 候选逐条核实并补写行为契约后按归位宪法回灌登记簿；unused 候选逐条排除动态调用误报后再定状态机；未建图则纯 agent 扫描不受影响
3. **填充图书馆**：按骨架逐卷撰写。顺序：00-overview → 10-architecture → 20-modules → 30-features → 40-guides → 90-reference → 最后更新 INDEX.md
   - **馆外存量四态盘点**（建馆期一次性判定，防孤儿回流）：①馆内 ②非文档资产（vendor/第三方/生成物/夹具——不收编）③工具链豁免（agent 工具目录与引导文件——位置由工具链决定，不收编）④待归位（真·馆外知识文档——收编入馆或入棺归档）。`doclib place list` 给出待归位清单与建议归宿，逐份判定，禁止整目录豁免
4. **自检**：执行下方"覆盖度清单"，全过才算完成
5. **收尾**：运行 `doclib verify`，然后 `doclib snapshot --note "initial build"` 固化基线

## 反克隆铁律

- 禁止成段搬运源码。文档承载的是**行为、契约、设计意图、验收标准**，不是字节
- 允许 ≤10 行的示意片段用于澄清歧义（精确的报错文案、正则、协议样例等）
- 写"它保证什么"，不写"第几行干了什么"
- 禁止信息倾倒：表格承载枚举事实，叙述承载动机与机制——一篇文档只剩表格与条目 = 卡片库不是图书馆

## 面穷举清单（防遗漏——umami 首轮教训制度化）

建馆的核心失败模式是"面没穷举"：馆漏了什么，重建就缺什么（对比对象是**原仓库**，差距=缺陷）。以下四类面必须**逐项成条目**，禁止注记带过：

1. **API/命令面全枚举**：源仓库的每一个端点/CLI 命令/子命令（含子资源路由、变体入口）逐条登记进登记簿——**"注记"（如'子路由同某契约'）不能替代条目**；枚举法：route 文件树 / proto 服务 / 命令注册表全量 grep，与登记簿条目数对账
2. **页面/路由面全枚举**：SPA/站点的每个页面（含详情页、子页、模态、变体）登记 routes 册；页面路径形态（是否带 locale 前缀、路由组结构）必须**显式记载**
3. **资产结构形态**：静态资产的组织形态（目录结构/命名模式/数量）必须写明（如"语言包按 `<dir>/` 子目录组织"vs 平铺）——形态错了复原就结构性跑偏
4. **隐藏语义深挖**：派生写入/端点分流/多态归属/缺省值/约束（长度/枚举/策略）——凡 handler 内联逻辑须读码落卷（umami 的 revenue 派生/热图 record 分流/sourceId 多态均为漏网重灾区）

## 写作方法论（文体学——PRD §7.6）

馆藏文档分三类文体，识别优先级：frontmatter `type` 字段 > 卷默认映射。

**narrative 叙述书（讲理解，给人读）**——教科书五段，三段硬性：

1. **导读**：H1 之后首个非空段落（不加 H2），一段话说清本文讲什么、读完能得到什么——兼作人与 agent 的摘要锚点（可复用进 _index 摘要）
2. `## 为什么`：动机、背景、设计决策与被否备选——回答"项目为什么长这样"
3. `## 是什么`：概念、结构、职责边界——回答"它是什么、由什么组成"
4. `## 怎么运转`：行为、流程、边界与错误——回答"它怎么工作"
5. `## 怎么验收` / `## 参考`（可选）：可执行验收标准（30-features 默认要有）、交叉引用

允许增补自定义段落，不可缺标准段（机器按固定措辞检查）。各卷侧重：模块书（20-modules）侧重边界契约、功能书（30-features）侧重行为+AC、架构书（10-architecture）侧重选型理由与决策。

**ledger 登记簿册（供查询，给机器）**——首段为册导读（本册范围/图例/状态说明），其后五要素条目；大表格在此合法。

**index 索引页**——INDEX/_index/README 按既有规范。

**卷默认文体**：10/20/30/40/50/70/80=narrative；60/90=ledger；00-overview=豁免；95-lessons 按既有"现象/根因/解决/规避"规范（豁免结构检查）；99-archive 与根 README/INDEX 豁免。

**配比与粒度**：一篇书回答一个主题；正文 <10 行且 <400 字符即卡片化回炉（机器门禁 strict；status: draft 的骨架文档降级为警告）；>300 行考虑按主题拆分（分册阈值 30 篇不变）；**注记污染禁令**——实验编号（S2-05、D-18 等）、答卷日期、"实测补/暂记复原口径/回灌补记"等工作痕迹字样禁止出现在馆内正文（差异知识改写为正式段落）。

## 各卷写作要点

- **00-overview/feature-map.md 是全馆之锚**：必须穷尽所有用户可感知行为（页面/接口/CLI 命令/后台任务/定时任务/配置开关），每项标注对应文档。复原者按它验收
- **10-architecture**：技术选型必须带理由与约束（为什么是它、不是什么替代品）；数据模型给到字段级；关键决策写 ADR（决策/背景/被否备选/后果）
- **20-modules**：每卷讲清职责边界、对外契约（输入/输出/错误）、内部关键流程；frontmatter 的 `covers` 指向该模块的代码目录或文件
- **30-features**：每个功能一份行为规格，含**可执行的验收标准**（Given/When/Then）。这是 90% 复原度的量化基础，宁可多不可漏
- **40-guides/rebuild-plan.md**：复原的施工顺序——按依赖关系分阶段（脚手架 → 数据层 → 核心域 → 接口层 → 次要功能 → 打磨），每阶段给出依据文档与完成标准
- 所有文档的 `covers` 必须填写真实代码路径（文件或目录），它是日后增量更新的锚点

## 覆盖度清单（自检，全过才算完成）

- [ ] feature-map 与 30-features/ 一一对应，无遗漏功能
- [ ] 20-modules 卷清单与 10-architecture 的模块清单一致
- [ ] INDEX.md 收录全部文档且每条摘要准确
- [ ] 所有文档 frontmatter 的 covers 指向真实存在的路径
- [ ] rebuild-plan.md 的阶段覆盖全部模块与功能，依赖顺序成立
- [ ] 随机抽 5 个源文件，其行为都能在图书馆中找到归属文档
- [ ] **面穷举对账**：route/proto/命令枚举数 == 登记簿条目数；页面枚举 == routes 册条目数；无"注记代条目"残留
- [ ] **资产形态已记载**：i18n/静态资产/路由形态（前缀/分组）显式成文
- [ ] **文体合规**：叙述文档含导读 + 为什么/是什么/怎么运转三段；正文无注记污染字样（实验编号/答卷日期/复原口径/实测补/回灌补记）；`doclib check` 文体违规为 0
- [ ] 终极抽查：假装陌生的自己，只凭图书馆回答——怎么部署？核心数据流是什么？任一功能的边界行为？错误处理策略？配置项全集？——答不上来的部分回炉重写
