# 功能规格索引

> 每个功能一份行为规格（`30-features/<功能名>.md`），与 00-overview/feature-map.md 一一对应。规格含**可执行验收标准**（Given/When/Then），是复原验收与日常开发验收的共同基准。

## 验收标准与双跑答卷规范（F14 同题共答）

每条验收标准必须**可执行、可双跑**：同一标准在原仓库与复原仓库（或任意实现）各跑一遍后，结果可逐条 diff。每条验收条目须包含：

1. **条目号**：功能内唯一（如 `AC-01`）
2. **Given / When / Then**：前置 / 动作 / 断言（含错误路径的期望）
3. **可复现命令**：仓库根可执行的确切命令
4. **期望结果**：确定性预期（输出/状态/错误码），禁止"正常工作"类模糊表述
5. **运行时声明**：node/依赖版本、环境前置（DB/端口/服务），双跑同构执行的前提

**断言可观测性纪律**：每条 Then 必须落到**可观测证据**（HTTP 状态码/响应体形状/DB 行数/退出码），并注明取证方式（curl -w、psql、jq）；"行为达成"类主观描述不可验收。契约细节（方法/参数/形状/状态码）**从响应与代码实证，不从文档转抄**——凭证载体（body token vs cookie）、成功状态码（200 vs 201）、重定向码（302 vs 307）等高频失真点须逐项实测。

**答卷格式**（双跑执行者按此逐条记录，与 doclib-accept skill 同构）：

```text
条目号 | 输入/动作 | 期望 | 实测 | 一致? | 证据
```

答卷文件与规格分离存放（如 `50-testing/benchmark/0xx-*-answer.md`），原仓库卷与复原卷同构——diff 两卷即同题共答结果，一致率即复原度得分。
