## 交互语义缺口（8 条 · ADR 触发证据）

契约册已建（73 条），但下列交互语义在**现有卷结构**里仍无天然归宿：

| # | 缺口 | 为什么无处安放 |
| --- | --- | --- |
| G-1 | Toast 堆叠顺序 / 去重 / 自动消失时长 | 属**瞬时反馈**，既非功能规格也非组件规格 |
| G-2 | 触屏 / 指针通道差异（拖拽激活阈值、边缘自动滚动） | 响应式卷只管断点不管**手势通道**；契约册画布语义是鼠标语义 |
| G-3 | 命令面板模糊匹配算法、分组与键盘导航细节 | 契约册只到「输入关键词→过滤」一层，算法属 cmdk 内行为 |
| G-4 | 数据表列排序 / 筛选 / 分页的受控状态、URL 同步、加载态 | 组件册只登记组件名；功能卷只写业务筛选语义 |
| G-5 | 对话框 / 抽屉的焦点陷阱、层叠与滚动锁定的应用层覆盖 | 属可访问性语义，ui-layer 只写到「Radix 保证」 |
| G-6 | 离开页面 / 切换步骤时**未落库改动的竞态语义** | 自动保存已写，「未落库即离开」的失败语义无落点 |
| G-7 | 签名板笔迹的量化语义（采样密度、缩放、导出分辨率） | 落在签名板组件与 pdf-pipeline 之间，**两卷各持一半** |
| G-8 | 嵌入态宿主尺寸变化 → 画布 scale 的传播时机 | 响应式卷讲了画布与断点耦合，未覆盖嵌入态传播 |

> 判据 ≥3 条 —— **已触发**载体 §4.3 的 ADR 提案（`doclib/10-architecture/decisions.md` ADR #27）。
