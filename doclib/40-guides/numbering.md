# 编号推进规则

> 本仓一切账本编号的唯一发号纪律——feature-map 功能号、ADR 决策号、PRD 版本、产品版本、馆内三位序号、基准项目序号皆在此列。任何 agent 取号前必读；直接动机是 2026-10-28 的并发撞号实证（两个实例同轮各自取用 feature #44 与 ADR #28，双双撞车后返工换号）。

## 为什么

账本编号是全馆引用体系的锚点：progress 引 feature 号、规格引 ADR 号、AC 引章节号——锚点一旦歧义，对账与历史全盘失真。三个真实压力源：**并发写入是常态**（多实例协作，凭对话记忆取号必然撞车）；**编号膨胀稀释信息**（9 天 28 则 ADR 中若混入口径修正类条目，「结构性裁决」的信号就被噪声淹没）；**误改号毁史**（已发布的引用永不成立 if 编号被复用）。

## 是什么

五条纪律，约束所有会发号的账本：

1. **先查账末，后取号**——取号前读账本实际最后一行，取 max+1；禁止凭记忆、凭对话上文、凭规划草稿取号。多账本联动时逐本各查（feature-map 与 decisions 互不同步，各查各的）。
2. **一号一事，永不换号**——编号绑定不可变的事实：ADR 号绑定决策本身（被推翻标 Superseded 指新决策），feature 号绑定功能条目。内容修订不换号；账本 forward-only。
3. **膨胀约束**——只有结构性裁决才占 ADR 号（口径修正、数字校正并入既有 ADR 的后果栏或入 lessons）；只有产品功能/仓库门面级变化才立 feature-map 条目（修正类走 progress 补记不占号）；PRD 版本每会话至多 bump 一次；产品版本（package.json）仅发布时 bump；描述性修订不占任何号。
4. **序号槽位步进**——馆内文件三位序号（010/020/…）按主题族 10 步进取空闲槽，禁止跳号预留私有槽；区间用尽时扩位升宽（050 族用尽扩 0500 宽度），永不改既有号；50-testing/benchmark 项目档案按 100/110/…190 步进，用尽扩 200 段。
5. **执行前并发重核**——动账本前 `doclib status` 看漂移与基线归属、读账末行复核；发现同号异事以账本为准，本任务换下一号并在载体留痕；已登记的号永不回收。

## 怎么运转

取号动作 = 读账末 → max+1 → 即时登记（禁止预留空号 gap）。引用既有编号时以账本内描述核对语义，防「同号已易主」的悬挂引用（规则 2 保证不换号，此为二重防护）。撞号一旦发生：换号 + 教训实时入 `95-lessons/`（一行制）。本规则的执行面分层：取号前查账与并发重核由引导纪律约束（本文档 + 开发宪法指针）；撞号属语义问题，check 的确定性判定面无法穷尽，归 audit 抽查兜底——确定性语义分层铁律（ADR #15）的又一实例。
