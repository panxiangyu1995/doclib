# 复原基准测试指南（Reconstruction Benchmark）

> 图书馆完备度无法自证——内容再全面也难以证明"特别全"：写文档的人不知道自己漏了什么（未知的未知），只有只凭文档做事的复原者能显形缺口。
> 本指南沉淀 2026-10-19 方法论讨论（用户拍板 + 五项补强），规格见 PRD F14（v0.19）。执行本指南前请先读 PRD F14 与 F3。

## 为什么（目的铁律——最高优先级，一切对比以此为纲）

**重建产物 ↔ 原仓库 的实质性差距，才是图书馆缺陷的显影器。**

- 对比对象是**原仓库**，不是图书馆——"重建满足图书馆"只证明馆自洽（循环论证），不证明馆完备：馆漏写了什么，重建就缺什么，而这正是要抓的缺陷
- 同题共答（验收标准双跑）只是**辅助手段**：验收标准本身来自馆，馆缺了它就测不到——故同题共答通过 ≠ 复原合格
- 每轮复原后，主持方（源侧）必须执行**实质差距对比**：API 面全枚举 diff / 页面与路由 diff / 资产结构形态 diff / 行为语义抽查 / i18n 与非功能面——每个差距归因三类：**馆缺陷**（漏写/写不清/注记未成条目 → 回灌）、**复原范围取舍**（E 组合法）、**复原实现偏差**（对齐）
- 修复闭环：馆缺陷 → 回灌；方法论缺陷 → 改本指南与 skills；系统性缺口 → CLI 增强

### 三阶段模型【用户拍板，分阶段实现】

| 阶段 | 目标 | 完成判据 | skill/CLI 支撑 |
| --- | --- | --- | --- |
| **P1 信息零遗漏** | 原仓库的信息 100% 入馆、100% 进重建——"因馆遗漏而缺"清零 | 面穷举对账平衡（API/页面/rpc 枚举 ↔ 登记簿 Δ=0）；重建↔原仓库无"馆遗漏"项 | build skill 面穷举清单；**CLI `verify` 面穷举对账守卫（已实现）** |
| **P2 质量保证** | 重建的行为语义与原仓库完全一致（形状/参数/边界/错误面），实现门禁全绿 | 行为层双跑一致率 100%（含边界与错误路径）；typecheck/lint/test/build 门禁全绿 | accept skill 行为一致性断言；S2 类语义深挖回灌；门禁清单（50-testing） |
| **P3 升华超越** | 复原产物**优于原仓库**：修掉原仓库的 bug、补齐体验短板、文档化增强 | 升华提案清单（bug 修复/改进项）逐条评估采纳并记录于档案——复原不再是终点而是超越的起点 | rebuild skill 升华提案阶段；档案增"升华清单"（bug 修复/改进/反馈源项目回灌） |

> 三阶段串行推进：P1 未清零不做 P2 判定；P2 未一致不做 P3 提案评估。每阶段的证据都落在复原档案（010 系）中。
>
> **图谱加速（可选，v0.30 起）**：源项目已建知识图谱（`.codegraph/`）时，P1 面穷举以 `doclib graph draft` 候选兜底、P2/S2 深挖与 P3 升华挖掘用 `doclib graph explore` 定位——图输出仅候选，证据仍以实测为准；Q40 三指标（建馆耗时/查询耗时/缺口发现率）在下轮基准实验埋点事后验证。

## 是什么

一套七步操作闭环（选项目→建馆→隔离复原→同题共答→缺陷分类→对症下药→回归重跑）× 三阶段模型（P1 信息零遗漏→P2 质量保证→P3 升华超越）× 四分类缺陷账（内容/结构/表述/验收）；配套准入标准、污染防护与复原档案制度——档案落 50-testing/benchmark/ 分区。

## 原理

**复原即基准测试**：给多个现有开源项目建图书馆 → 通过图书馆从零复原开发这些项目 → 对比原仓库与复原仓库的差异 → 差异即图书馆缺陷显影 → 对症下药完善 → 回归重试。这是文档领域的 TDD：图书馆是代码，复原是测试，差异是失败用例。

多项目交叉验证防过拟合：单项目校准会让基线迁就该项目特性；**多项目共性缺陷**才是 12 卷基线/登记簿 schema 演进的实证依据（裁决 PRD Q15/Q25/Q26）。

## 怎么运转（操作闭环七步）

1. **选基准项目**：按下方准入标准挑选，登记入复原档案
2. **建馆**：对原仓库执行 doclib-build（按 skill 方法论），`doclib snapshot` 固化基线
3. **隔离复原**：新环境执行 `doclib plan --rebuild`，复原者**只读图书馆**（信息隔离铁律，F3）；REBUILD 任务书与 plan stdout 均含 revision（入馆写前比对乐观锁）；见"污染防护"
4. **同题共答**：同一套验收标准在原仓库与复原仓库**双跑**，逐条对比行为结果；结构对齐度由 agent 评审辅助
5. **缺陷分类**：每个差异按四分类入账（见下）
6. **对症下药**：内容缺陷回灌补账；结构缺陷触发基线/PRD 演进；表述/验收缺陷改 skill 与模板
7. **回归重跑**：图书馆结构版本变更后必跑（见"回归触发"）

## 基准项目准入标准

- **体量**：小中型（单 agent 数日可复原）——CLI 工具、小型库、小型应用；不选框架级巨物
- **多样性**：覆盖不同领域（后端服务/CLI/前端应用/数据处理）——不同领域暴露不同卷的盲区（如 80-design 只有前端项目能测）
- **生态**：宽松协议（MIT 等）、活跃维护（对比有基准）、入口清晰
- **切片复原**：大项目按功能切片部分复原，局部缺陷同样可暴露

## 同题共答（对比分层）

| 层级 | 对比物 | 判定 |
| --- | --- | --- |
| 行为层（主） | 同一套验收标准双跑（原仓库 vs 复原仓库），逐条对比结果 | 不一致 = 图书馆缺陷 |
| 结构层 | 模块职责/数据流/依赖对齐度（agent 评审） | 偏差 = 结构叙述不足 |
| 字节层 | **不对比**——代码风格/命名/quirk 是设计值（PRD 非目标） | 无意义 |

## 缺陷四分类账（每个差异必须分类）

| 类别 | 判定 | 行动 |
| --- | --- | --- |
| 内容缺陷 | 该项目图书馆漏写某功能 | 项目级补账（回灌流程，PRD Q6） |
| 结构缺陷 | 某类知识在 12 卷/登记簿 schema **装不下** | 产品级：触发基线/PRD 演进——多项目共性暴露的结构缺陷是基线演进的实证依据 |
| 表述缺陷 | 写了但复原者读出歧义 | skill 方法论改进（怎么写才算清楚） |
| 验收缺陷 | 验收标准不可执行/结果不可比 | 30-features 模板改进 |

## 复原档案（每基准项目一份）

- 基准项目标识与准入记录（领域/体量/协议）
- BUILD 基线版本号（snapshot id）
- REBUILD-LOG.md（复原全过程留痕 + **复原者身份**）
- 差异清单（同题共答结果）
- 缺陷分类账（四分类逐项）
- 修复记录（回灌/演进/改进动作与对应 PRD/基线变更）

## 污染防护（关键，易忘）

- 建馆与复原必须使用**不同会话/不同实例**——**理想为不同模型**
- 失效模式：同一 agent 先建馆再复原，先验知识（记忆中的源码）让复原"过顺"，缺陷不暴露，校准失真
- REBUILD-LOG 必须记录复原者身份（会话/实例/模型），用于审计隔离有效性
- 若条件所限只能同模型，至少保证全新会话且不向复原会话透露任何源码细节

## 回归触发

- 图书馆**结构版本变更**（基线分类法/登记簿 schema/条目五要素调整）→ 该基准项目**必跑**完整回归
- 图书馆**内容更新** → 抽查跑（受影响功能切片）
- 回归结果对比历史复原档案：复原度得分不回退为通过；回退 = 本次"改进"引入了退化，须复盘

## MVP 实验清单（首轮）

1. 拍板首个基准项目（PRD Q31，拟用户最熟悉领域、小中型、宽松协议）
2. 跑通全闭环 1 次：建馆 → 隔离复原（不同模型/实例）→ 同题共答 → 缺陷四分类 → 回灌/改基线
3. 产出首轮复原档案与复原度得分；结构缺陷汇入 PRD 演进
4. 复盘方法论本身（本指南修订），再扩基准库至 3–5 个领域样本

## 首轮复盘（2026-10-21 · umami 全闭环实证）

MVP 首轮已闭环：umami 建馆（97% 覆盖/治理 A）→ 隔离复原（opencode/minimax-m3.1-flash-free，异模型合规）→ 同题共答 **96.4%**（53/55 双侧一致）→ 缺陷四分类 D-01~D-18 + S1×7 + S2×24 + S3×8 + D32/E13 复核 → 回灌/修复全落账。zod 基准在另一环境并行（待回收）。

**方法论修订（首轮实证沉淀）**：

1. **契约修正必须全馆 sweep**：同一契约散落登记簿+规格+数据流+术语表多处，src 侧发现失真只改登记簿会制造馆内自相矛盾（S1 七项的根因）——修正后必须 grep 旧值复查清零；登记簿为契约单点（Q29），规格引用之
2. **答卷即裁决书**：双跑答卷逐条留痕（状态码/响应体/DB 行数）使分歧可归因——首轮 2 项分歧全部追溯到馆内矛盾而非复原者过错；AC 断言必须可观测（30-features 模板已增纪律）
3. **证据裁决复原者猜测**：S2 深挖中复原者一正（限流 5/15）一误（IP 入指纹）——凡猜测必以源码/实测证据裁决后回灌
4. **D/E 复核三分类**：D 组自行决策逐条复核为 A（与源一致）/B（偏差→回归对齐清单）/C（工程适配）；B 类清单即回归轮的复原侧工作项——首轮 13 条
5. **执行顺序纪律**：破坏性操作（reset 等）放采样序列最后——首轮 reset 误伤后续采样制造过伪分歧
6. **切片复原边界合法**：E 组 13 条（react-zen/云模式/21/45 路由/契约铺满）属复原范围取舍，不计图书馆缺陷——档案须记录 E 组防误判
